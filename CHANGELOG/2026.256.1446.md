# 2026.256.1446 — feat: package the charly-lib shared plugin host + symlinks

## Summary

Cut `charly-openwrt` packaging over to the **shared plugin host** (opencharly/sdk#256, packagekit
hard cutover opencharly/sdk#258). Diff items:

1. new `charly_lib_version` input (pinned, default `v2026.256.1131`);
2. a "Download the charly-lib shared plugin host" step — fetches `charly-lib-linux-{amd64,arm64}`
   + `*.providers`, builds the plugins dir as `charly-lib` + `plugin-<word>` **symlinks**, and
   installs that same layout under `/usr/lib/charly/plugins` for the local `charly`;
3. the per-plugin binaries tarball download/extract is DELETED;
4. the install-test asserts the cutover **end-to-end**: the default variant's welded
   `plugin-<word>` set asserted **explicitly** (independent of manifest filenames) — each a symlink
   to `charly-lib` with its `.providers` — each **served** by the host (handshake read from a FIFO
   with a bounded `read -t 3`, asserting the `grpc` field, no blind delay), plus a **charly-level
   discovery** assertion (`charly --help` lists the welded words registered from the `.providers`
   manifests);

The install-test no longer runs the blanket `charly doctor` smoke. **Operator sign-off:** the
maintainer directed this cutover and signed off on replacing that smoke with the end-to-end
shared-host assertions above (explicit layout + per-plugin serve + charly discovery); the broader
`charly doctor` host-capability check is tracked by its named batch **opencharly/charly#609**. The
Pages upload root is `repo/`, so the fetched `.charly-lib/` staging is outside it (never published).

`charly generate-packages` stages the host **once** + symlinks, so the per-plugin re-linked
SDK/spec closure leaves every `ipk`. The loader contract (`.providers` beside an executable named
`plugin-<word>`) is unchanged.
